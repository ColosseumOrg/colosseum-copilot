# Tooling reference

Solana is a specialist set, not a required stack. Inspect the existing repository and the user's constraints first. These are dated research recommendations; "last verified" below means the cited upstream source was reviewed on that date, not that every package combination was executed. Refresh primary documentation before a consequential choice and pin the combination you actually test.

Anchor, Agave CLI, modular Rust crates, Kit, plugins, test tools, and code generators do not share one version number. The reviewed Anchor 1.1.x starting profile paired CLI/crates 1.1.2 with Solana CLI 3.1.10, Rust >=1.89, and separately pinned JavaScript packages. Treat this as a source-derived starting profile, not a reproduced compatibility guarantee. Preserve lockfiles and run the relevant example before endorsing the resolved set.

Prefer the highest-level program framework that meets measured constraints. Dean Little and Blueshift's low-level work supports profiling, explicit invariants, independent-reference tests, and honest maturity labels; a contributor's reputation does not establish that every repository is production-ready.

## Crypto-wide pointers

The supplied tooling research establishes Solana depth and transferable engineering practices, not a verified default stack for every chain. For another ecosystem, start from that project's official documentation and installed dependencies, obtain current primary evidence, and report the coverage limit. Do not recommend Solana solely because this list is longer.

| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |

Use [Grid recipes](grid-recipes.md) for supplementary crypto ecosystem metadata and fresh primary reads for current technical choices. Do not equate metadata counts with adoption or markets. Keep evidence discovery separate from recommending a tool; this reference does not automatically add candidates to Colosseum's public resources.

Before a new integration, disclose source/transaction/query egress and permissions. Hosted scanners may receive private code; RPC services receive requests. Follow [build-methods.md](build-methods.md) for executed verification and [frames.md](frames.md) for optional paid data.
